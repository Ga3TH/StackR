# StackR — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** Construire StackR, un remplaçant sécurisé de Laragon pour Windows 10/11 (Apache, PHP, MySQL, Mailpit, Node, Composer), avec interface Fluent et CLI.

**Architecture :** `StackR.Core` contient toute la logique (manifest, téléchargement vérifié, configs, sites, hosts, CA, services) derrière des interfaces testables. `StackR.App` (WPF + WPF-UI) et `StackR.Cli` (System.CommandLine) ne sont que des façades sur `StackREngine`. Le CLI sert aussi d'élévateur UAC pour l'écriture du fichier hosts.

**Tech Stack :** .NET 10 LTS (`net10.0-windows`), C# 14, WPF, WPF-UI 4.x, CommunityToolkit.Mvvm 8.x, Microsoft.Extensions.Hosting 10.x, System.CommandLine, xUnit + FluentAssertions-free (assertions xUnit natives).

**Spec :** `docs/superpowers/specs/2026-11-25-stackr-design.md`

**Niveau d'agent par tâche** (demandé par l'utilisateur) : indiqué `[haiku]`, `[sonnet]` ou `[opus]` dans chaque titre.

## Global Constraints

- Cible : Windows 10 22H2 et Windows 11, x64. `TargetFramework` = `net10.0-windows` partout.
- Aucun service n'écoute ailleurs que sur `127.0.0.1`.
- Tout binaire téléchargé est vérifié par SHA-256 **avant** extraction ; mismatch = fichier supprimé + `IntegrityException`.
- URLs du manifeste : `https://` uniquement ; canal `stable` uniquement.
- Aucun droit admin pour l'usage courant ; seule exception : `stackr hosts sync` (relancé via UAC).
- Racine par défaut : `C:\StackR`. Les chemins peuvent contenir espaces et accents.
- Secrets : DPAPI `DataProtectionScope.CurrentUser`.
- Bloc hosts : délimiteurs exacts `# >>> StackR` et `# <<< StackR`. Domaine : `.test`.
- Ports par défaut : HTTP 80, HTTPS 443, MySQL 3306, Mailpit UI 8025, Mailpit SMTP 1025.
- Interface en français par défaut (ressources `.resx`, anglais en secondaire).
- `Nullable` activé, `TreatWarningsAsErrors` = true.
- Ne jamais toucher à `C:\laragon`. Ne jamais `git push`.
- Commits terminés par `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Laragon (ou autre) occupe déjà 80/3306** → StackR identifie le processus propriétaire (nom + PID), n'en démarre aucun à moitié, affiche « Port 80 utilisé par httpd.exe (PID 1234) ». Test : Task 11 `StartAll_PortBusy_ReportsOwnerAndStartsNothing`.
2. **Dossiers `www` aux noms bizarres** (`Mon Projet`, `Été_2026`, `.git`, `a..b`, 70 caractères) → nom `.test` slugifié valide ou dossier ignoré ; jamais de nom non validé vers hosts. Test : Task 7 `SiteName_FromFolder_Cases`.
3. **Racine avec espaces/accents** (`C:\Dossier é\StackR`) → configs Apache/MySQL/PHP avec chemins entre guillemets et slashs `/`. Test : Task 6 `Render_PathWithSpacesAndAccents_IsQuotedForwardSlash`.
4. **Téléchargement interrompu / hash faux / annulation** → rien dans `bin\`, temp supprimé, erreur claire. Tests : Task 4 `Mismatch_DeletesFile`, Task 10 `Install_Failure_LeavesNoPartialFolder`.
5. **App tuée pendant que les services tournent, PID recyclé** → au redémarrage, un PID de `state.json` n'est considéré comme « nôtre » que si le chemin de l'exécutable est sous `bin\` ; jamais de kill d'un processus étranger. Test : Task 11 `Reconcile_ReusedPid_IsNotOurs`.
